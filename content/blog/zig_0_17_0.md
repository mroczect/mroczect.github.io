## Zig 0.17.0 udah rilis, ini yang berubah

oke jadi akhirnya Zig rilis versi **0.17.0** nih. ini rilis yang lumayan gede, bukan patch kecil doang.

angkanya:

- **5 bulan kerja**
- **925 commit**
- **206 kontributor**

sebelumnya tuh katanya diprediksi bakal lebih pendek. tapi ternyata jadi gede karena **Build System dirombak total**, plus **ELF Linker** di-enhance sampe Incremental Compilation bisa jalan buat semua orang di x86_64-linux.

versi ini dikasih nama kode **"Carmen the Allocgator"**. iya, aligator yang jago alokasi memory. aku juga nggak tau kenapa harus aligator, tapi ya udah lah ya.

---

## 1. Target Support: Sekarang Lebih Banyak

jadi Zig itu support banyak arsitektur sama OS. nah di rilis ini ada beberapa perubahan:

### Yang baru di-support:

- **aarch64-openbsd** sekarang di-test native di CI Zig. jadi kualitasnya bakal lebih terjaga.
- **aarch64-freebsd** dan **aarch64-netbsd** CI-nya sekarang jalan di pull request juga, bukan cuma di master.
- **loongarch32-linux-gnu** — target baru.
- **64-bit SPARC** — terutama **sparc64-linux**. ini bisa jalan berkat ELF linker baru Zig, yang support target ini lebih bagus daripada LLD.
- **x32** dan **N32 ABI** di x86-64 dan MIPS 64-bit. ini ABI niche yang pake instruksi 64-bit tapi pointer-nya 32-bit. tujuannya trade address space buat memori yang lebih hemat.
- **Game console** — `aarch64-switch`, `arm-gba`, `mipsel-psx`, `powerpc-wiiu`.
- **xtensa-linux** — masih early banget, cuma bisa lewat C backend atau LLVM backend eksperimental.
- **arc-linux**, **csky-linux**, **m88k-openbsd** — support di std lib kalau pake C backend.

### Yang di-drop:

- **powerpc-linux-gnueabi[hf]** — di-drop karena glibc cuma support "double-double" format di target ini, sementara Zig pake IEEE.
- **powerpc64-linux-gnu** — di-drop karena glibc nggak officially support ELFv2 di big endian.

### CPU baseline yang berubah:

beberapa target punya baseline CPU baru:

- `aarch64-haiku` → cortex_a55
- `m68k-*` → M68030
- `mips64-openbsd` → octeon
- `powerpc-netbsd` → 750
- `s390x-*` → arch11
- `sparc-linux` → v9
- `sparc64-*` → ultrasparc
- `xtensa-*` → esp32

## 2. Tier System: Level Support Zig

Zig bagi level support target jadi 4 tier:

### Tier 1

- Semua fitur bahasa non-eksperimental jalan.
- Compiler bisa generate machine code tanpa LLVM.
- Fuzzer jalan.
- **Cuma x86_64-linux yang Tier 1.**

### Tier 2

- Std lib abstractions ada.
- Stack traces jalan.
- libc ada walau cross-compiling.
- CI build module tests tiap push.

### Tier 3

- Bisa generate machine code via LLVM.
- Linker bisa produce object files, libraries, executables.

### Tier 4

- Bisa generate assembly atau C source code doang.

**OS minimum version:**

- Darwin 15.0+
- DragonFly BSD 6.4+
- FreeBSD 14.0+
- Linux 5.10+
- NetBSD 10.1+
- OpenBSD 7.8+
- Windows 10+

## 3. Language Changes: Bahasa Zig Ikut Berubah

banyak banget perubahan bahasa di rilis ini. ini yang penting-penting:

### @bitCast diubah definisinya

`@bitCast` sekarang punya definisi baru: reinterpret **logical bit representation**.

bedanya:

- nggak boleh lagi bitcast dari `extern struct` atau `extern union`.
- operasinya sekarang **endian-agnostic** — sama aja di little atau big endian.

kalau butuh "type punning" (reinterpret memory), pakai `@ptrCast` atau `extern union`.

contoh yang dulu jalan, sekarang error:

```zig
const TwoBytes = extern struct {
    b0: u8,
    b1: u8,
};
const bytes: TwoBytes = .{ .b0 = 0x12, .b1 = 0xAB };
const int: u16 = @bitCast(bytes); // ERROR di 0.17.0
```

gantinya pakai `@ptrCast`:

```zig
const int_ptr: *align(1) const u16 = @ptrCast(&bytes);
```

### Grammar Zig Sekarang Di-fuzz

dulu, grammar formal Zig (`grammar.peg`) sama implementasi aslinya tuh nggak 100% match. nah sekarang udah dibenerin. jadi ada single source of truth buat grammar Zig. ini penting buat future grammar changes.

### @cImport Dihapus

`@cImport` udah deprecated di 0.16.0, sekarang **beneran dihapus**. gantinya pakai package eksternal:

```sh
zig fetch --save git+https://codeberg.org/ziglang/translate-c
```

terus di `build.zig`:

```zig
const Translator = @import("translate_c").Translator;
// ...
const translator: Translator = .init(translate_c, .{...});
```

### Builtin Baru

- **`@backingInt`** dan **`@fromBackingInt`** — pengganti `@intFromEnum` dan `@enumFromInt`.
- **`@divCeil`** — pembagian integer yang dibulatkan ke atas. contoh: `@divCeil(5, 3) == 2`.
- **`@SpirvType`** — bikin tipe SPIR-V (sampler, image, dll) langsung dari Zig.

### Syntax yang Dihapus

- `void{}` → sekarang harus `{}` aja.
- `errdefer |err|` → capture-nya dihapus.
- `i0` → tipe integer yang nggak masuk akal ini dihapus.
- `internal` dan `link_once` global linkage → dihapus.
- Array multiplication syntax `a ** b` → ganti pakai `@splat`.

contoh migrasi:

```zig
// Dulu
var result = [1]u8{0} ** 10;

// Sekarang
var result: [10]u8 = @splat(0);
```

### @hasDecl Sekarang Cuma Untuk Public

dulu `@hasDecl` return `true` buat deklarasi public **dan** deklarasi di file yang sama. sekarang cuma public aja. biar konsisten.

## 4. Standard Library

beberapa perubahan di std lib:

### Yang baru:

- `@exp` dan `@exp2` sekarang support **f128**.
- `std.Io.Semaphore.waitTimeout` — nunggu semaphore dengan timeout.
- `std.spirv` helpers buat sampling, querying, writing images.
- `std.fs.path` ada appending variants buat relative dan resolve.

### Deprecations:

- `std.heap.memory_pool.AlignedManaged` → ganti pakai `std.heap.memory_pool.Aligned`.
- `std.heap.memory_pool.ExtraManaged` → ganti pakai `std.heap.memory_pool.Extra`.
- `std.builtin` → deprecated, ganti pakai `std.lang`.
- `std.meta.fieldInfo`, `fieldNames`, `fieldTypes` → deprecated, ganti pakai `@typeInfo`.
- `std.DoublyLinkedList.pop` → ganti pakai `popLast`.
- `std.gpu` → rename jadi `std.spirv`.

### ArrayList:

- `getLastOrNull` → rename jadi `last()`.
- `getLast` → deprecated, pakai `last().?`.
- `lastPtr` → baru, return `?*T`.

### SafeAllocator Introduced

`std.heap.DebugAllocator` diganti sama **SafeAllocator** yang thread-safe. guarantee-nya:

- `deinit` lapor semua leaks dan free semua memory.
- Semua allocation mismatch → panic atau segfault.
- Double free → panic atau segfault.
- Nggak reuse memory — jadi writes after free bakal segfault.

`std.heap.DebugAllocator` dan `std.heap.Check` udah deprecated.

### fmt.allocPrint dipindah ke mem.Allocator

```zig
// Dulu
try std.fmt.allocPrint(arena, "{s}={d}", .{ x, y });

// Sekarang
try arena.print("{s}={d}", .{ x, y });
```

### bit_set Renames

- `std.bit_set.IntegerBitSet` → `std.bit_set.Integer`
- `std.bit_set.ArrayBitSet` → `std.bit_set.Array`
- `std.DynamicBitSet` → deprecated, ganti `std.bit_set.DynamicManaged`

### lang.OptimizeMode → lang.Optimize

Tag-nya juga di-rename:

- `Debug` → `debug`
- `ReleaseSafe` → `safe`
- `ReleaseFast` → `fast`
- `ReleaseSmall` → `small`

## 5. Build System: Ini yang Paling Gede

### Maker Process Dipisah dari Configurer Process

dulu, `zig build` itu jalanin semua di satu executable. sekarang dipisah:

- **Configurer** — yang baca `build.zig`, ngatur konfigurasi.
- **Maker** — yang eksekusi build graph.

kenapa dipisah? biar:

- Maker nggak perlu di-rebuild tiap edit `build.zig` — cuma dibangun sekali waktu pertama install Zig.
- Maker dibuild dengan optimizations enabled — lebih cepet.
- `build.zig` logic bisa di-skip kalau CLI flag yang dipake nggak butuh.

efeknya: `zig build` jadi lebih cepet.

### Cache System Dirombak

fitur baru:

- **Directory support** — file added/removed/renamed di folder bikin cache invalid.
- **Metadata mode** — kalau size, inode, atau mtime berubah, cache invalid.
- Format cache diganti jadi **binary** — hemat ~25% ukuran file.
- Ada `zig cache-cat` buat debug isi cache.

konon katanya cache hit jadi 5-10% lebih cepet.

### "Cache Poisoning"

ini konsep baru. kalau cache di-"poison", artinya konfigurasi punya side effects yang nggak bisa di-track sama cache.

contoh: kalau `build.zig` ngecek "apakah `scdoc` ada di sistem?" buat nentuin default option — itu cache-nya kotor.

solusinya: pakai fungsi baru kayak `dependOnFileContents`, `dependOnDirectoryMetadata`, dll. biar dependensinya eksplisit.

CLI option baru:

```
--cache-poison[=mode]
    pure        (default) Avoid false positive cache hits
    poisoned    Don't cache the configuration
    disallowed  Panics when cache would be poisoned
    ignored     A little poison never hurt anybody
```

### findProgram Dipisah

- `findProgram` — cari executable segera, tapi poison cache.
- `findProgramLazy` — nggak poison cache, return `LazyPath`.

### Build Server Protocol

kalau pass `--listen=-`, build system bakal serve protocol yang ngijinin client (kayak IDE) monitor dan control build graph.

ini yang bikin **ZLS (Zig Language Server)** sempet broken di 0.17.0. tapi tim Zig sama tim ZLS lagi kerja sama buat benerin.

## 6. Compiler: Incremental Compilation

ini fitur yang banyak ditunggu-tunggu. sekarang **Incremental Compilation** udah jalan buat project-project di **x86_64-linux**.

cara pakainya:

```sh
zig build -fincremental --watch
```

artinya: Zig bakal mantau perubahan file, terus rebuild incremental kalau ada yang berubah. jadi nggak perlu build from scratch tiap kali edit kode.

### SPIR-V Backend

- Sekarang **multi-threaded** kayak backend lain.
- Execution modes (LocalSize, OriginUpperLeft) sekarang derived dari calling convention.
- `spirv_task` dan `spirv_mesh` calling conventions baru.
- 22 bug fixed.

### WebAssembly Backend

- Sekarang passing **2060/2054 (100%)** behavior tests dibanding LLVM backend.
- Tapi belum default di debug mode karena debug info belum support.

## 7. Linker

### ELF

ELF linker baru udah makin matang:

- Full x86_64 support.
- Full SPARC64 support.
- Partial Loongarch support.
- Static library generation.
- Shared library generation.
- DWARF debug info.
- Mostly-reproducible binaries.

masih belum default, tapi udah bisa build sebagian besar project Zig di x86_64-linux.

### COFF

COFF support di linker udah ditambahin:

- Output `.obj` dan `.lib`.
- Output implibs.
- TLS support.
- `__dllimport` support.
- Support `.drectve` arguments.
- Bisa link ke `-gnu` dan `-msvc` libc.

### New Linker Testing Framework

Zig sekarang pake **snapshot-based testing** buat linkernya. Jadi bisa compare objdump output, run artifacts, dan check linker errors.

command-nya:

```sh
zig-debug build test-link -Dtest-filter=my-test
zig-debug build test-link -Dtest-filter=my-test -Dlink-snapshot-update
```

## 8. Toolchain

### LLVM 22

Zig 0.17.0 upgrade ke **LLVM 22.1.8**. Ini nge-cover Clang (`zig cc`), libc++, libc++abi, libunwind, sama libtsan.

### Loop Vectorization Tetap Dimatiin

di rilis sebelumnya, tim Zig terpaksa matiin **loop vectorization** karena miscompilation. fix-nya udah ada di LLVM main branch, tapi belum masuk LLVM 22. jadi workaround-nya masih aktif.

Zig 0.18.0 bakal upgrade ke LLVM 23, baru bisa diaktifin lagi.

### libc Versions

- **musl 1.2.5** (+ backported fixes)
- **glibc 2.44**
- **Linux 7.2 headers**
- **macOS 27.0 headers**
- **NetBSD 11.0 libc**
- **OpenBSD 7.9 libc**
- **WASI libc** commit tertentu
- **MinGW-w64** commit tertentu

### zig objdump

ini tool baru buat nge-dump objek files. kepake banget buat snapshot testing sama ngembangin COFF Linker.

command example:

```sh
zig objdump mathtest.dll --all-headers
zig objdump mathtest.dll --exports --only-symbol=add
```

### zig fmt --complexity

flag baru buat ngitung tokens dan AST nodes. gunanya buat ngukur seberapa kompleks perubahan kode kamu, lebih insightful daripada line count.

contoh output:

```
info: src/link/Elf/gc.zig: tokens=1538 nodes=770
info: src/link/Elf/Atom.zig: tokens=15576 nodes=7768
info: total: tokens=97031 nodes=47621
```

## 10. Roadmap Selanjutnya

yang bakal dikerjain di rilis berikutnya:

- Kerja bareng tim ZLS buat enhance Build Server Protocol.
- Complete Windows support di x86_64 backend.
- Complete dan stabilize bahasa.
- aarch64 backend jadi default buat debug mode.
- Enhance Linker, hilangin dependency ke LLD.
- Fuzzer yang kompetitif sama AFL.
- Transisi dari library dependency LLVM ke process dependency Clang.
- Audit Standard Library.
